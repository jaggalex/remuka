# Оператор установки и операторская консоль

ТЗ к **ADR-259**. Статус: этапы 1–2 реализованы, 2026-11-23. Сводит в одно всё, что делает человек,
который управляет установкой, и закрывает найденные разрывы между ТЗ. Заменяет разделы
`spec/payment-providers.md` §6.1 (роль) и §6.3 (место консоли); их содержание по деньгам
остаётся в силе.

Прежде чем менять код, прочитайте `AGENTS.md`, ADR-094 (команды и аудит), ADR-178 (RLS),
ADR-248, `spec/payment-providers.md` §6, `spec/billing.md` §4, `spec/account-deletion.md`,
`spec/legal-acceptance.md`, `spec/pulse.md`, `content/legal/*/rules`.

## 0. Два уровня управления

| Уровень | Кто | Что делает | Где |
| --- | --- | --- | --- |
| **Администратор организации** | клиент: владелец команды, школы, семьи | приглашает, выдаёт роли, блокирует участников, смотрит журнал своей организации, платит | уже есть: диалог организации (`spec/IAM-v1.md`) |
| **Оператор установки** | вы, тот, кто держит сервер | метрики, клиенты, деньги, жалобы, запросы на данные | этот документ |

«Админки» в смысле режима, где видно и можно всё, у Ремуки нет и не будет. Оператор не видит
содержимого комнат: это защищает клиентов и вас (меньше доступа — меньше ответственности по
ПДн).

**Найденные разрывы, которые закрывает этот документ:**

1. `pnpm operator:grant` обещан в `payment-providers.md` §6.1, но не реализован: функция
   `grantInstanceOperator` в базе есть, команды нет. Первого оператора можно создать только
   SQL-запросом.
2. Возврат денег обещан в оферте, Terms и `billing.md` §4.3, но команды `billing:refund` нет.
3. Правила использования обещают отключение ссылки, приостановку организации, объяснение
   причины и обжалование. Механизма для этого нет: есть только блокировка участника
   администратором организации.
4. Учётная запись оператора защищена только паролем, хотя через неё идут деньги и удаление
   аккаунтов по `--now`.
5. Консоль описана в двух местах (`/operator` для денег и `/operator/pulse` для метрик) без
   общей структуры.
6. Для поддержки нет способа посмотреть «кто этот клиент, какой у него тариф и платежи», кроме
   SQL.

## 1. Правила

1. **Роль выдаётся только с сервера.** Кто имеет доступ к серверу, и так управляет всем;
   выдача роли через интерфейс создала бы путь повышения прав. Ни одного маршрута API, который
   выдаёт роль, нет.
2. **Роль — своя в каждой установке.** У ЕС и РФ разные базы и аккаунты; оператора назначают
   в каждой отдельно.
3. **Без доступа к содержимому комнат.** Оператор видит метаданные (организация, тариф, число
   участников и комнат, даты, платежи), но не тексты, изображения и комментарии. Если по жалобе
   нужно увидеть содержимое — его присылает заявитель (ссылка, скриншот), а не открывает
   оператор.
4. **Каждое действие — команда с причиной и аудитом** (ADR-094). Консоль вызывает те же
   команды, что и CLI: один механизм. Действие без `reason` отклоняется.
5. **Сначала CLI, потом интерфейс.** Редкие и опасные действия могут остаться только в CLI.
   Частые и требующие обзора — получают экран.
6. **Подтверждение личности для изменений.** Консоль открывается только с двухфакторным
   входом (`spec/totp.md`, ADR-260): чтение — с кодом не старше 12 часов, изменяющие действия —
   не старше 15 минут. Денежные действия в консоли включаются следующим этапом; до этого —
   только в CLI.

## 2. Роль оператора

Команды (реализовать; функция в `apps/sync/pg/payment-providers.mjs` уже есть — перенести
её в `apps/sync/pg/operators.mjs`, без дублирования):

```
pnpm operator:grant  --email <адрес> --reason "..."
pnpm operator:revoke --email <адрес> --reason "..."
pnpm operator:list
```

- `grant` требует существующий аккаунт с подтверждённым e-mail.
- `revoke` отказывает, если это последний оператор установки.
- **Автор обязателен.** Каждая изменяющая команда называет автора через `--as <id|email>` или
  `REMO_OPERATOR`; без него команда отказывает с подсказкой. Роль `instance_operators`
  проверяется всегда, и `created_by`/`actor_id` никогда не `null` (поправка к ADR-259
  «god-mode через CLI закрыт»).
- Каждая команда пишет строку `audit_events` (`operator.granted`, `operator.revoked`) с
  `reason` и автором.
- **Первый оператор.** После выкладки зарегистрироваться в приложении обычным образом,
  подтвердить e-mail, затем на сервере:
  `pnpm operator:grant --email <адрес> --as <адрес> --reason "bootstrap"`. Первый оператор
  называет сам себя: других операторов ещё нет, а безымянная выдача — это и есть god-mode,
  который поправка закрывает. Это шаг в `docs/operations/cloud.md` для каждой установки.

## 4. Жалобы и меры

Новая таблица `operator_actions`: `id`, `kind`, `subject_type` (`board_link`, `board`, `org`),
`subject_id`, `reason_internal`, `reason_public`, `report_ref` (номер письма или обращения),
`created_by`, `created_at`, `reverted_by`, `reverted_at`. Вне tenant-RLS, как
`instance_operators`.

```
pnpm abuse:link-disable  --link <id>  --reason "..." --public "..."
pnpm abuse:board-hide    --board <id> --reason "..." --public "..."
pnpm abuse:org-suspend   --org <id>   --reason "..." --public "..."
pnpm abuse:revert        <action-id>  --reason "..."
pnpm abuse:list          [--open]
```

- **Отключение ссылки** — публичная ссылка перестаёт открываться (`404` для посетителя), в
  комнате для участников — плашка «Ссылка отключена оператором: {reason_public}».
- **Скрытие комнаты** — комната недоступна всем, кроме администраторов организации; данные не
  удаляются.
- **Приостановка организации** — `orgs.suspended_at`, `orgs.suspension_ref`. API и sync отвечают
  `ORG_SUSPENDED` (тот же код, что в `IAM-v1.md` для участника); экспорт и бэкап для
  администраторов организации остаются доступны.
- **Объяснение причин.** Каждая мера отправляет администраторам организации письмо
  `operator_action` (RU/EN): что сделано, `reason_public`, как обжаловать — ответом на
  `abuse@<домен зоны>`. Это требование правил использования и Digital Services Act.
- **Восстановление** — `abuse:revert` с причиной и письмом о восстановлении.
- Мера с `--now` без письма не существует: письмо уходит всегда.

## 5. Консоль `/operator`

Одна страница с разделами, видна только `instance_operators`; остальным — `404`. Маршруты
сервиса — `/operator/...`, снаружи — `/api/operator/...` (nginx снимает `/api`), как у
остальных API.

| Раздел | Содержимое | Этап |
| --- | --- | --- |
| **Пульс** | `spec/pulse.md` §6 | 2 |
| **Клиенты** | поиск по e-mail, организации, номеру счёта; карточка: организация, источник, тариф и подписка, счета и платежи, число участников и комнат, даты, принятые документы, меры оператора, ссылка на переписку в Chatwoot. Без содержимого комнат | 2 (только чтение), 3 (действия) |
| **Деньги** | `spec/payment-providers.md` §6.3: подключения, мёртвые события, возвраты, кредиты, ручные оплаты | 3 (после TOTP) |
| **Жалобы** | открытые меры, создание меры по ссылке на комнату, восстановление | 4 |
| **Журнал** | действия операторов из `audit_events` с фильтрами | 2 |

- Каждое изменяющее действие — форма с обязательной причиной и кодом из приложения
  не старше 15 минут (правило 6).
- Консоль строится на `@remo/ui`; плотные таблицы, не карточки.
- В каждой установке своя консоль. Клиенты, деньги и журнал видны только в своей установке.

**Этап 2 (реализовано).** Страница `/operator` в клиенте; сервис отвечает на `/operator/...`
(снаружи `/api/operator/...`). Каждый запрос проверяет `instance_operators` и отвечает `404`
всем остальным, включая вошедших без роли:

| Маршрут | Что отдаёт |
| --- | --- |
| `GET /operator/session` | кто оператор, когда последний раз вводил код (`mfa_at`), сколько резервных кодов осталось |
| `POST /operator/session/confirm` | код из приложения (`challenge` из `403 MFA_REQUIRED`); пишет `mfa.step_up` |
| `GET /operator/pulse?weeks&currency&zone` | шесть плиток, рост, вовлечённость, деньги, здоровье; `zone` — `all` или код зоны |
| `GET /operator/customers?q=` | поиск по e-mail, названию организации и номеру счёта |
| `GET /operator/customers/user/<id>` / `org/<id>` | карточка без названий и содержимого комнат |
| `GET /operator/journal?action&actor&org&from&to` | `audit_events` с причиной и автором |

Пульс читает только `metrics_daily` (`spec/pulse.md` §4.6): живых запросов к событиям и
биллингу нет. Чего посчитать нельзя (нет базы метрик, день не пересчитан, нет когорты),
показано как «—» с причиной. Обмен агрегатами между зонами (`spec/pulse.md` §5) собирает
установка ЕС; фильтр показывает «Все», «ЕС» и «РФ». Установка РФ только отвечает и показывает
свою зону с причиной.

Маршрутов, изменяющих `instance_operators` или деньги, на этапе 2 нет: консоль читает.
Код из приложения пишется в `sessions.mfa_at` (`spec/totp.md` §6): чтение — 12 часов,
изменение — 15 минут через `assertOperatorStepUp`. `sessions.operator_confirmed_at`
обновляется тем же вводом и остаётся историей подтверждения личности.

## 6. Реферальная программа

**Решение: на запуске реферальной программы с вознаграждением нет.**

- То, что в `spec/pulse.md` называется источником, — это метки в ссылках и сайт, с которого
  пришёл человек. Денег и наград там нет.
- **Партнёрам** (авторам каналов, сообществам) выдаётся ссылка с меткой
  `?utm_source=<партнёр>`. Сколько регистраций, активаций и оплат она дала, видно в Пульсе.
  Если нужно поблагодарить — промокод для его аудитории (`billing:prices`, скидка — уже есть),
  а не выплата.
- **Если позже понадобится «приведи команду»** — только кредитом на услуги, без выплат денег:
  «пригласивший и приглашённая организация получают по месяцу Pro, когда приглашённая впервые
  оплатит». Кредит уже есть в биллинге (`spec/billing.md` §3.5). Это будет отдельное ТЗ
  с защитой от накруток.
- **Почему без денежных выплат.** Выплата вознаграждения человеку — это договор с ним (агентский
  или иной), документы на каждую выплату и, в зависимости от статуса получателя, удержание
  налогов. Скидка или кредит на услуги уменьшает цену для клиента, отдельной выплаты не
  возникает. Как именно отражать скидки и кредиты в учёте ИП — подтвердить у бухгалтера.

## 8. Этапы

1. **CLI-разрывы:** `operator:grant/revoke/list`, `customer:show`, `billing:refund`,
   `billing:credit`, `abuse:*` с таблицей `operator_actions`, `orgs.suspended_at` и письмом
   `operator_action`. Шаг «первый оператор» в `docs/operations/cloud.md`.
2. **Консоль, только чтение:** каркас `/operator`, Пульс, Клиенты, Журнал; повторный ввод пароля.
   *Сделано: `/operator` в клиенте, `/operator/*` в сервисе с ролью и `404`, Пульс на
   `metrics_daily`, ночной агрегатор и `pulse:recompute`, карточка клиента, журнал аудита,
   подтверждение пароля в сессии, обмен агрегатами зон (`spec/pulse.md` §4–§5).*
3. **TOTP для операторов** (§7), затем действия в Клиентах и раздел Деньги.
   *Сделано (ADR-262, `spec/operator-actions.md` §3–§4.2):* маршруты возврата, отметки
   оплаты, кредита, тарифа и мер; `operator_requests` с `requestId`; та же функция, что у
   CLI; step-up не старше 15 минут; экраны Клиентов и Денег; канал и фактор в журнале.
4. **Жалобы** в консоли.
   *Сделано (ADR-262, `spec/operator-actions.md` §4.3):* открытые меры, новая мера по ссылке
   на комнату или организации, снятие меры и те же письма `operator_action` с адресом
   обжалования зоны.

## 9. Приёмка

- [x] `pnpm verify` зелёный, с наборами базы.
- [x] `operator:grant` на неподтверждённый e-mail — отказ; на подтверждённый — роль и строка
      аудита с причиной и автором; `operator:revoke` последнего оператора — отказ; без `--as`
      обе команды отказывают (`operator-role*.test.mjs`).
- [x] Нет ни одного маршрута API, изменяющего `instance_operators` (тест по маршрутам).
- [x] `customer:show --email` выводит тариф, подписку, счета, принятые документы и меры, без
      названий комнат и содержимого; то же доказывает консольный запрос карточки
      (`operator-console.db.test.mjs`).
- [x] `billing:refund` на тестовом подключении проводит возврат, пишет аудит и письмо клиенту;
      без `--reason` и без `--as` — отказ.
- [x] `abuse:link-disable` — посетитель по ссылке получает 404, участники видят плашку,
      администраторы организации — письмо с причиной и адресом обжалования своей зоны;
      `abuse:revert` возвращает всё и шлёт письмо; без `--as` мера не создаётся.
- [x] `abuse:org-suspend` — API и sync отвечают `ORG_SUSPENDED`, экспорт для администраторов
      работает.
- [x] `/api/operator/*` для не-оператора — 404 (юнит и база). Готовность отказа для
      изменяющего запроса без свежего кода — `assertOperatorStepUp`; самих изменяющих
      маршрутов на этапе 2 нет.
- [x] Консоль установки РФ не показывает клиентов ЕС, и наоборот; Пульс на установке ЕС
      показывает обе зоны из `metrics_daily` (свою и `provenance = 'peer'`), на установке РФ —
      свою зону с причиной. Клиенты и журнал читают только свою базу (по построению).
