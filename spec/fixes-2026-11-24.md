## 1. Из комнаты не выйти на главную; логотип открывает меню профиля

**Причина — наше решение, а не ошибка кода.** ADR-266 §2 (шапка из 8 элементов) сделал логотип
входом в меню аккаунта, а «Все комнаты» — строкой этого меню. В коде так и есть:
`BoardTopbar.tsx:283` — клик по `BrandMark` открывает `menu === "account"`. Привычка людей
(и прежняя Ремука) — «логотип = домой». Путь к комнатам стал на два клика длиннее и спрятан.

**Предложение.**
- Логотип = **«Все комнаты»** (переход на главную), подсказка «Все комнаты · G R».
- Рядом с названием — **путь**: «Ромашка › Ретро · спринт 14 ▾». Клик по «Ромашка» — тоже на
  главную, отфильтрованную по команде; по названию — меню комнаты (как сейчас).
- Меню профиля открывается только аватаром справа (элемент 8). Строка «Все комнаты» в нём
  остаётся — третий путь не мешает.
- Правка ADR-266 §2 (элемент 1) и ADR-274; поправить артборды «Убранный стол» и
  «Меню профиля» (там написано «логотип открывает то же меню»).

Решить: **да / нет** (рекомендую да).

## 2. «Журнал вызовов» (доказательный журнал) — неуправляемый список

**Что сейчас.** `AgentsPanel.tsx:286` рендерит `AiJournal` внутри раздела агентов
организации: список растёт без серверной пагинации, на одной странице с настройками.
В макете волны 5 это ещё и отдельная вкладка «Журнал вызовов».

**Предложение.**
- **Убрать из интерфейса организации** (и вкладку из макета `App-AgentsAdmin`). Сам журнал
  (хэш-цепочка, записи на каждый вызов) на сервере остаётся — это доказательная база, её не трогаем.
- В разделе «ИИ» оставить одну строку-сводку: «Вызовов за месяц: 128 · расход 64 ₽ ·
  цепочка проверена» и ссылку «Выгрузить журнал (CSV)» для администратора.
- **Полноценный просмотр — на будущее, в бэклог (5.x):** вкладка в консоли оператора и/или
  страница «Журнал ИИ» с серверной пагинацией, фильтрами (период, скилл, ключ, итог),
  поиском по задаче и выгрузкой. Делать, когда появится реальный спрос (аудит, споры о расходах).

Решить: убрать сейчас + сводка + выгрузка — **да / только убрать**.

## 3. Значок (эмодзи) комнаты пропал; нужна картинка для визуального поиска

**Что сейчас.** Эмодзи **не пропал**, его стало не найти: кнопка в `WorkspaceHome.tsx:614`
появляется только при наведении на плитку и нарисована иконкой **агента** (`icon="agent"`, искра),
поэтому её не узнают. Обложек/превью у комнат нет: плитка показывает только эмодзи или
общую иконку.

**Как делают другие.**
- **Miro:** у доски есть миниатюра; её можно выбрать из готовых картинок, загрузить с
  компьютера или **выбрать область доски** (Change thumbnail → Select board area). В недавнем
  обновлении Miro урезал эту возможность — пользователи жалуются, что пропала визуальная навигация,
  при этом выбор любого эмодзи вместо 40 встретили хорошо.
- **Figma / FigJam:** по умолчанию миниатюра — снимок содержимого первой страницы;
  «Set as thumbnail» назначает обложкой **любой фрейм**, рекомендуемый размер 1920 × 1080 (16:9).
  Слабое место — миниатюра обновляется не сразу.
- **Notion** (по памяти, без проверки): значок-эмодзи + обложка-картинка страницы.

**Предложение «значок + обложка» — три уровня, от бесплатного к ручному.**
1. **По умолчанию — живое превью** содержимого комнаты: тот же рендер, что у экспорта
   PNG, по области «всё содержимое», пересчитывается в фоне не чаще раза в 10 минут после
   изменений. Ничего настраивать не нужно — у каждой комнаты сразу своя картинка.
2. **«Сделать обложкой»** в контекстном меню фрейма (как у Figma): обложка = этот фрейм,
   обновляется вместе с ним. Самый «правильный» путь: обложка — часть комнаты.
3. **Загрузить картинку** — через уже существующий конвейер изображений.

**Ограничения (чтобы не раздувать хранилище и главную).**
- Обложка хранится **одна**, уже уменьшенной: 640 × 360 (16:9), WebP, обрезка по центру
  («cover»), предел ≈ 150 КБ; оригинал загруженной картинки не храним.
- Загрузка — те же форматы и предел 20 МБ на входе, что у изображений; в квоту хранилища
  идёт только итоговые ≈ 150 КБ.
- Превью строится из данных комнаты — значит, видно только тем, у кого есть доступ к
  комнате (без утечки содержимого в общий список).
- **Значок-эмодзи остаётся** (маленький, рядом с названием и в шапке комнаты); выбор — из
  любого эмодзи с поиском, не 40 штук.

**Где управлять.** На главной у плитки — постоянная (не только по наведению) кнопка «⋯» →
«Обложка и значок»; в комнате — меню названия → «Обложка и значок». Иконку «агент» с кнопки
убрать (она обманывает).

**Объём.** Значок (поиск, видимость) — S; живое превью — M (фоновый рендер, хранение,
инвалидация); «Сделать обложкой» и загрузка — M.

Решить: какие уровни берём сейчас — **(а) значок + живое превью**, **(б) + обложка из
фрейма**, **(в) + загрузка**. Рекомендую (а)+(б) сейчас, (в) — следом.

## 4. Реакции в «Провести» не появляются

**Причина найдена — ошибка в реестре команд (T5).** В `commandsChrome.ts:205–219` у команд
реакций id `run.reaction.like` / `…love` и т. д., а `run` вызывает
`ctx.run("run.reaction.0")` — по **индексу**. Обработчики в `BoardTopbar.tsx:247` записаны по
`command.id`. Ключи не совпадают → клик ничего не делает. Тестом это не поймано.

**Вторая проверка:** свою реакцию человек видит только если `presence` содержит его же сессию
(`ReactionsLayer` строит всплески из `presence`). Проверить при исправлении; если себя там нет —
показывать свой всплеск локально сразу по клику.

**Как должно выглядеть (предложение по поведению, правка ADR-104).**
- Реакция всплывает **снизу видимой области**: старт — нижние 15 % экрана, X — случайно в
  средних 80 % ширины; плывёт вверх ~60 % высоты за 2,4 с с лёгким покачиванием по X
  (±12 px) и угасанием. Несколько подряд — не слипаются (разный X и задержка).
- Если выделен объект — как сейчас: всплывает от объекта (это осмысленная привязка).
- Без привязки к центру экрана. С «Спокойными анимациями» — короткая вспышка на месте без полёта.
- Тест: e2e «клик по реакции → элемент всплеска появился у отправителя и у второго участника».

Решить: **поведение «снизу вверх» — да**; привязку к выделенному объекту **оставить / убрать**.

## 5. Новый объект не всегда в верхнем слое

**Причина.** ADR-039: порядок = `widget.z ?? rankOf(type) * 1000`. Новые объекты создаются
**без `z`**, поэтому их слой решает тип: новая фигура окажется **под** любым стикером (у
стикеров ранг выше), и под всем, что когда-то поднимали «наверх» (у них явный большой `z`).

**Предложение.** Каждый созданный объект (инструментом, вставкой, дублированием, агентом,
серией, протягиванием) получает `z = max(layerKey всех объектов) + 1` в той же транзакции.
Одна функция в `@remo/doc` (`topZ(board)`), вызывается всеми путями создания.

Исключение, которое стоит оставить: **новый фрейм** ложится поверх других фреймов, но **под**
содержимым, которое он накрывает при создании (иначе его тело на 75 % закроет стикеры). Новый
**канбан/таблица** — наверх, как все.

Решить: исключение для фрейма — **да / нет**.

## 6. Tab на карточке канбана создаёт новую фигуру

**Что видно в коде.** Перехват Tab (`useBoardKeyboard.ts:282`) работает только для стикера
и текста; для карточки `preventDefault` не вызывается, и Tab уходит в браузер — фокус
переходит к следующему фокусируемому элементу. На холсте это кнопки «+» продолжения
(`EdgeContinueLayer` — настоящие DOM-кнопки, доступные по Tab) и элементы рейки; отсюда и
неожиданное создание. Точный путь до фигуры подтвержу воспроизведением при исправлении.

**Предложение.** Tab на выделенной карточке канбана — **ничего не создаёт** и не уводит фокус
с холста (`preventDefault`). Позже можно дать Tab смысл «следующая карточка в колонке»
(бэклог), но не сейчас. Плюс общее правило: Tab на холсте вне поля ввода либо делает действие
объекта, либо ничего — фокус в DOM-кнопки слоёв не проваливается.

Решить: **да**.

## 7. Комментарий к выделенному объекту встаёт не там, где кликнули, и его не сдвинуть

**Причина.** ADR-105: якорь `widget` хранит **только id объекта**; булавка всегда рисуется в
одной точке — середина верхнего края объекта (`CommentsPanel.tsx:151`: `x + width/2, y`).
Точка клика выбрасывается. Перетаскивания булавок нет вовсе.

**Предложение (правка ADR-105).**
- Якорь объекта хранит ещё **смещение внутри объекта** в долях: `{kind:"widget", widgetId,
  fx, fy}` (0…1 от рамки). Булавка встаёт ровно в точку клика и едет вместе с объектом
  (в том числе при повороте и изменении размера).
- Комментарий «к выделенному» без клика (кнопка/клавиша) — в правый верхний угол объекта
  (`fx: 0.9, fy: 0.1`), дальше можно сдвинуть.
- **Булавку можно тащить:** внутри того же объекта — меняется смещение; на другой объект —
  перепривязка к нему; на пустой холст — становится якорем-точкой. Отмена одним ⌘Z. Тащить
  может автор и модератор; остальным — курсор «нельзя».
- Старые треды без `fx/fy` рисуются как сейчас (середина верха) — миграции нет.

Решить: **да**.
