# «Убранный стол»: механики

> Задания для разработки с границами и приёмкой — `spec/dev-plan-character.md`.

ADR-266. Статус: 2026-11-23. Принцип и визуальные правила — `spec/character.md` §3.6 (ADR-265).
Макет: холст «Ремука — лендинг и продукт», артборд «Волна 1 · Убранный стол: шапка комнаты»
(https://claude.ai/artifact/QzwXA5ViAxFMjiQeZKbxWR#artboard-App-RoomTidy).

Это ТЗ — о поведении, без которого принцип нельзя выполнить: где окажется спрятанное, как его
найти, когда хром притихает и откуда мы знаем, что можно спрятать. Внешний вид — по макетам.

## 0. Что есть и чего нет

| Механика | Сейчас | Нужно |
| --- | --- | --- |
| Поиск команд | нет | ⌘K / Ctrl K, общий реестр команд (§1) |
| Меню-намерения | 16 элементов в шапке, свои меню у фасилитации, «⋯», аккаунта | 8 элементов, меню строятся из реестра (§2) |
| Состояние сохранения | иконка-облачко всегда | только «Сохраняем…» дольше 2 с, «Нет связи», «Остановлено» (§3) |
| Зрители | отдельная иконка-глаз со счётчиком, в том числе «0» | в группе аватаров «+N», ноль не показывается (§4) |
| Боковые панели | могут быть открыты несколько | одна за раз (§5) |
| Подсказки | `CanvasHint` — один раз на браузер, без учёта действий | общий механизм «пока не освоил» (§6) |
| Хром во время работы | всегда одинаковый | притихает при жестах на холсте (§7) |
| Спокойные анимации | атрибут `data-motion="calm"` без переключателя | настройка аккаунта (§8) |
| Данные о нажатиях | нет | событие `chrome.used` и раздел Пульса (§9) |
| Постепенное раскрытие в диалогах | вручную в каждом | компоненты `Disclosure` и `DangerZone` (§10) |

## 1. Реестр команд и поиск ⌘K

### 1.1 Реестр

Реестр — это существующий список команд объектов `apps/web/src/commands.ts` (ADR-050), который
уже питает контекстное меню и правую панель. Он расширяется командами хрома и поверхностью
`palette` (поиск ⌘K); отдельного файла-реестра не заводится. Новые поля — ниже; поля `group`,
`icon`, `menuTitle` для контекстного меню — `spec/canvas-character.md` §3.

```ts
interface Command {
  id: string;                       // "room.export", "run.timer", "view.theme.dark"
  title: I18nKey;                   // как в меню
  synonyms: { ru: string[]; en: string[] }; // «выгрузить», «скачать», "download"
  intent: "invite" | "run" | "agent" | "room" | "account" | "canvas" | "help";
  shortcut?: string;                // отображение; обработка — в существующем keymap
  available(ctx): true | { reason: I18nKey }; // роль, тариф, состояние комнаты
  run(ctx): void;
  danger?: boolean;                 // показывается внизу меню и с подтверждением
}
```

- Меню «Провести», «Агент», меню комнаты, меню аккаунта и пункты «ещё» тулбара **строятся из
  реестра** по `intent`. Пункт, которого нет в реестре, нельзя добавить в меню: так меню и поиск
  не расходятся. Проверка — тест: каждый пункт меню имеет `id` из реестра.
- Горячие клавиши остаются в существующем keymap; реестр только показывает их.

### 1.2 Поиск

- Открывается: ⌘K / Ctrl K, кнопка «Найти действие» на нижней панели комнаты, пункт «Помощь →
  Найти действие». Не открывается, пока фокус в поле ввода или в редакторе текста на холсте.
- Поиск по `title` и `synonyms` на языке интерфейса и на английском; порядок: совпадение с
  начала названия → с начала слова → в синониме. Без запроса — 5 последних команд этого
  браузера и 3 предложения по контексту (есть выделение — команды выделения).
- Недоступная команда видна серой с причиной словами («Нужна роль редактора»,
  «Только на тарифе Team»); запуск — нет.
- Последней строкой, если агенты разрешены в комнате, — «Спросить агента: <запрос>». Открывает
  поручение агенту с этим текстом; сам ничего не выполняет.
- Пусто: «Такого пока нет. Попробуйте другое слово — или спросите агента» (голос §2 ADR-265).
- Доступность: `role="dialog"` с полем `role="combobox"` и списком `role="listbox"`, стрелки,
  Enter, Esc; фокус возвращается туда, где был.
- Последние команды — `localStorage` (настройки браузера, ADR-123), не больше 10 `id`.

## 2. Шапка комнаты: 8 элементов

| # | Элемент | Что внутри |
| --- | --- | --- |
| 1 | Логотип | меню аккаунта (то же, что 8): все комнаты, помощь |
| 2 | Путь и название комнаты ▾ | переименовать, свойства и доступ, экспорт (PNG, PDF, бэкап), скопировать ссылку; ниже черты — удалить. («История изменений» убрана: такой функции в продукте нет) |
| 3 | Аватары | до 4 участников, «+N»; по клику — список с ролями и зрителями, «следовать за» |
| 4 | Провести ▾ | таймер, голосование, показ фреймов, следовать за мной, реакции |
| 5 | Агент | поручить, план, журнал; с фиолетовым пунктиром (ADR-265) |
| 6 | Комментарии | счётчик новых, ноль скрыт |
| 7 | Позвать | основная кнопка экрана (коралловая) — доступ, ссылка, гости |
| 8 | Аккаунт | все комнаты, тема, язык, спокойные анимации, помощь и клавиши, выход |

**Чипы сессии — состояния, а не элементы (решение владельца 24.11).** Таймер и голосование —
пункты меню «Провести» (4). Пока идёт таймер — справа от «Провести» чип «04:12»; пока открыто
голосование — чип «Голосов: 22». Каждый появляется при запуске и исчезает по окончании
(правило 5 §3.6 ADR-265: состояние показывается, только пока оно активно), в счёт 8 элементов
не входит, по клику открывает «Провести» на своём разделе. Видят все участники комнаты.
На ширине < 900 px чипы сжимаются в точку на иконке «Провести». Последние 10 с таймера —
цифры `danger-ink`. В спокойной комнате в шапке ровно 8 элементов.

Уходят из шапки: отдельная иконка «все комнаты», кнопка ИИ, «⋯», облачко, помощь, глаз, переключатель
панели, кнопка показа, тема, язык. Каждый из них — команда реестра (§1) и пункт одного из меню.
Во время показа шапка заменяется панелью ведущего (уже есть в ADR-200).

На ширине < 900 px остаются 2, 3 (до 2 аватаров), 4 (иконка), 7, 8; остальное — в меню
аккаунта.

## 3. Состояние сохранения

| Состояние | Показ |
| --- | --- |
| `saved` | ничего |
| `pending` ≤ 2 с | ничего |
| `pending` > 2 с | «Сохраняем…» рядом с названием |
| `offline` | сразу: «Нет связи — правки подождут» (жёлтая плашка) |
| `blocked` / ввод остановлен | сразу: причина и что делать (как сейчас, ADR-084) |
| возврат к `saved` после `offline` | «Всё сохранено» на 2 с, затем ничего |

`aria-live="polite"` объявляет «нет связи» и «всё сохранено»; `pending` не объявляется.
E2e, которые ждут текст «saved» в `.save-state`, переходят на `data-state="saved"` (атрибут
остаётся на скрытом элементе).

## 4. Зрители и участники

Группа аватаров: до 4 кругов (агент — квадрат), затем «+N». Наведение и клик — список:
участники с ролями, зрители по ссылке числом («и 3 гостя смотрят»), «следовать за».
Счётчик зрителей отдельно не показывается; ноль не показывается нигде.

## 5. Одна боковая панель

`BoardPanels` держит одно поле `openPanel` (комментарии, инспектор, агенты, голосование, …).
Открытие другой закрывает текущую; Esc закрывает; выделение объекта не открывает панель само —
инструменты выделения живут в плавающей планке у объекта. Состояние не сохраняется между
визитами.

## 6. Подсказки «пока не освоил»

- `useOnceHint(id, { doneAfter: 3, maxSessions: 5 })` в `apps/web/src/hints.ts`: подсказка
  видна, пока действие не выполнено `doneAfter` раз **или** не прошло `maxSessions` визитов;
  затем — никогда. Учёт — `localStorage` (`remuka.hints.<id>`), без сервера.
- Действие отмечает себя: `markHintDone("canvas.doubleClickEdit")` в обработчике.
- Реестр подсказок — тот же файл; «Помощь → Показать подсказки снова» сбрасывает учёт.
- `CanvasHint` переходит на этот механизм; его текущий ключ «seen» считается выполненным.
- Одновременно видна одна подсказка.

## 7. Хром притихает во время работы

- Пока идёт жест на холсте (перетаскивание, рисование связи, изменение размера, рамка выделения,
  рисование фигуры) дольше 150 мс, шапка, тулбар и нижняя панель получают `.is-quiet`:
  прозрачность 0.35, `pointer-events: none`. Через 200 мс после конца жеста — обратно.
- Не притихает при работе с клавиатуры, при редактировании текста (там нужен формат-бар) и
  если в хроме открыто меню или диалог.
- `aria-hidden` не меняется: для чтения с экрана хром остаётся.
- С уменьшенным движением — без перехода, мгновенно.

## 8. Спокойные анимации

Настройка аккаунта «Вид → Спокойные анимации» (по умолчанию выкл.), хранится на сервере в
настройках пользователя и приходит с `/auth/me`; клиент ставит `html[data-motion="calm"]`.
Действует как `prefers-reduced-motion` (ADR-265 §4): длительности 0, нет пружин и парения,
курсоры коллег без пружины и буфера.

## 9. Данные: что нажимают

- Событие `chrome.used` в `METRIC_CATALOG`: `{ control }` из закрытого списка `id` реестра
  команд и элементов шапки; **первое использование за день на организацию** (как
  `feature.used`, `spec/pulse.md` §2). Без id людей и комнат.
- Пульс, раздел «Хром»: доля активных организаций за 28 дней, использовавших каждый
  элемент; пороги правила 2 §3.6: < 5 % — кандидат уйти глубже, > 40 % среди спрятанных —
  кандидат на постоянное место. Решение — владельца, раз в квартал, запись в ADR.

## 10. Постепенное раскрытие в диалогах

`@remo/ui`:
- `Disclosure` — «Ещё настройки ▾», закрыт по умолчанию, помнит состояние в пределах диалога.
- `DangerZone` — отдельная секция внизу диалога: заголовок, последствия словами, кнопка
  `danger`; отделена линией `line-soft`.
Диалоги доступа, комнаты, организации и аккаунта переходят на них при переделке по макетам.

## 10a. Тулбар, планки выделения, боковая панель (волна 1)

Макеты: «Волна 1 · Тулбар и панели выделения» и «Волна 1 · Свойства и комментарии».

**Тулбар.** Семь инструментов — выбор, стикер, фигура, текст, связь, фрейм, картинка — и
«Ещё»: карточка, таблица, канбан, комментарий, шаблоны (те же пункты — команды реестра, их
находит ⌘K). Отменить/повторить — отдельной группой под чертой, повторить серое, когда нечего.
Клик по активному инструменту открывает его варианты (цвет нового стикера, вид фигуры, тип
связи); выбор запоминается для следующих объектов в этом браузере (`localStorage`).

**Планка выделения** — над выделенным, не больше 7 элементов и «⋯». Состав и порядок:

| Выделено | Планка | В «⋯» |
| --- | --- | --- |
| Стикер | цвет, размер текста (Авто), жирный, чек-лист, ссылка, связать с…, ⋯ | выравнивание, цвет текста, размер стикера, копировать стиль, закрепить, удалить |
| Фигура | заливка, контур, толщина, вид фигуры, текст, связать с…, ⋯ | пунктир, уровень подъёма, выравнивание текста, копировать стиль, удалить |
| Связь | тип, толщина, пунктир, концы, цвет, подпись, ⋯ | поменять концы, размер и цвет подписи, удалить |
| Текст в правке | жирный, курсив, зачёркнутый, список, чек-лист, ссылка, ⋯ | подчёркнутый, нумерованный, код, отступы, очистить формат |
| Несколько | «N объектов», выровнять, разложить ровно, сгруппировать, цвет всех, ⋯ | распределить, собрать по типам, копировать, удалить |

«⋯» открывает боковую панель свойств (§5). Порядок кнопок пересматривается по `chrome.used`
(§9). У каждой кнопки — подсказка с клавишей.

**Боковая панель свойств:** заголовок — тип объекта; сверху самое частое (цвет — сетка
палитры, текст — Авто/A−/A+ и выравнивание), ниже `Disclosure` «Ещё настройки», внизу
`DangerZone` с «Удалить» и подсказкой «можно отменить ⌘Z».

**Комментарии:** вкладки «Открытые · N» и «Решённые · N»; тред — к какому объекту, сообщения
с аватарами цвета человека, поле ответа с `@`, кнопка «Решено» (зелёная, картон). Клик по
булавке на холсте открывает эту панель на треде. Пусто: «Все вопросы закрыты. Новые появятся
здесь — и булавкой на холсте».

## 11. Этапы

1. Реестр команд (§1.1) и меню из реестра; шапка из 8 элементов (§2); состояние сохранения (§3);
   аватары (§4). **Сделано 2026-11-24 (T5):** команды хрома с `intent`, синонимами RU/EN и
   поверхностью `palette`; шапка из 8 и её меню из реестра; `data-state` вместо текста «saved»;
   группа людей «до 4 + N» с ролями и зрителями; чипы таймера и голосования — состояния;
   тема и язык — в меню аккаунта.
2. Поиск ⌘K (§1.2).
3. Одна панель (§5), подсказки (§6), притихание (§7), спокойные анимации (§8); тулбар, планки
   выделения, панель свойств и комментарии (§10a).
4. `chrome.used` и раздел Пульса (§9); `Disclosure`/`DangerZone` (§10).

## 12. Приёмка

- [ ] Шапка комнаты на 1440 px — не больше 8 интерактивных элементов; на рабочем экране комнаты
      (без объектов холста) — не больше 12 (e2e считает `button, a, [role=button]` в хроме).
- [ ] Каждый пункт любого меню имеет `id` в реестре; каждая команда реестра находится поиском
      по названию и хотя бы по одному синониму на RU и EN.
- [ ] ⌘K не открывается из поля ввода; Esc возвращает фокус; недоступная команда показана с
      причиной и не выполняется.
- [ ] При сохранённом состоянии в шапке нет индикатора; «Нет связи» появляется сразу,
      «Сохраняем…» — только после 2 с.
- [ ] Ноль зрителей и ноль комментариев нигде не показаны.
- [ ] Открытие второй боковой панели закрывает первую.
- [ ] Подсказка про двойной клик исчезает после трёх правок двойным кликом; «Показать подсказки
      снова» возвращает её.
- [ ] Во время перетаскивания хром прозрачен 0.35 и не ловит клики; с клавиатуры — нет.
- [ ] «Спокойные анимации» включаются в аккаунте и действуют на другом устройстве после входа.
- [ ] Тулбар — 7 инструментов и «Ещё»; планка выделения любого типа — не больше 7 элементов и «⋯»; «⋯» открывает панель свойств; клик по булавке открывает тред.
- [ ] `chrome.used` пишется один раз в день на организацию и элемент; в Пульсе видна таблица.
