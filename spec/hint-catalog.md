# Каталог подсказок: слова — у операторов, правила — в коде

ADR-269. Статус: 2026-11-24, предложено владельцем. Развивает ADR-268 (сменные подсказки,
новости) и ADR-266 (подсказки «пока не освоил»), консоль — ADR-259/262.

> Задания для разработки — `spec/dev-plan-character.md` (T16).

## 0. Зачем и граница

Подсказки нужны во всём продукте, а их фразы должны меняться без выпуска версии: сотрудник
видит, что подсказку не понимают, и переписывает её сегодня, а не в следующем релизе.

**Граница:** оператор меняет **слова**, код решает **правила**.

| Решает код (слот) | Решает оператор (текст) |
| --- | --- |
| где подсказка живёт (экран, место) | формулировки вариантов |
| когда показывается (событие, условие, «пока не освоил») | какие варианты включены |
| кому (роль, тариф, есть ли люди в комнате) | порядок и паузы? — **нет**, порядок по визиту в коде |
| что в ней можно подставить (`{name}`, `{room}`) | — |
| максимальная длина, разрешена ли **жирность** | — |
| запрещённые места: деньги, удаление, безопасность, право, ошибки | — |

Почему не дальше: новое место или новое условие показа — это поведение продукта. Оно требует
тестов и доступности, и его нельзя проверить из консоли. Слова можно проверить автоматически.

## 1. Что попадает в каталог

- **Подсказки** всех экранов (реестр `apps/web/src/hints.ts`, ADR-266 §6, ADR-268 §2): пустые
  состояния (комната, главная, комментарии, журнал, поиск без результатов), первые действия
  (серия стикеров, связи, ⌘K, «следовать за», голосование), строка под приветствием без новостей.
- **Шаблоны новостей** (ADR-268 §3): по две-три формулировки на тип (`live`, `mention`, `agent`,
  `joined`) с подстановками.

**Не попадает:** подписи кнопок и меню, ошибки, юридические тексты, письма, тексты оплаты и
удаления. Это интерфейс и обязательства: они остаются в `i18n` и меняются с версией и тестами.

## 2. Слот (в коде)

```ts
interface HintSlot {
  id: string;                      // "room.empty", "home.lead.quiet", "news.mention", "tool.series"
  screen: string;                  // для консоли: где это видно
  description: { ru: string; en: string }; // для консоли: когда показывается
  intents: ("action" | "benefit" | "together")[];
  fields: ("title" | "body")[];    // пустая комната — заголовок и подзаголовок
  maxLength: { title?: number; body: number };
  placeholders: string[];          // ["name", "room"]; другие в тексте — ошибка
  bold: boolean;                   // разрешён ли **жирный**
  defaults: { ru: Variant[]; en: Variant[] };  // тексты по умолчанию — из i18n сегодняшнего кода
}
```

- Реестр слотов — один (`apps/web/src/hints.ts`); сервер получает его списком при сборке
  (`pnpm hints:slots` пишет `content/hints/slots.json`, проверка `hints:check` в `verify`).
- **Один механизм:** тексты подсказок уходят из `i18n` в `defaults` слота; клиент берёт
  опубликованный текст из каталога, а если его нет — `defaults`. Второго места для этих фраз
  не остаётся.

## 3. Хранение и выдача

- Таблица `hint_texts`: `slot_id`, `lang`, `variant_key`, `intent`, `fields jsonb`, `enabled`,
  `status` (`draft` | `published`), `version`, `updated_by`, `updated_at`. Опубликованная версия
  не меняется — правка создаёт новую; предыдущая остаётся для отката.
- Каждая установка — свои тексты (РФ и ЕС живут отдельно). Перенос между ними —
  `pnpm hints:export` / `hints:import` (JSON), импорт кладёт черновики, публикует человек.
- `GET /hints?lang=` → опубликованные тексты по всем слотам, несколько КБ, `ETag`; клиент
  берёт один раз за визит и кладёт в память. Публикация доходит до людей при следующей загрузке
  страницы — без живой рассылки.
- Нет таблицы, ошибка сети, пустой каталог — работают `defaults` из кода. Продукт без каталога
  выглядит как сегодня.

## 4. Консоль оператора: раздел «Слова»

- Список слотов по экранам: описание «когда показывается», текущие варианты RU и EN, доля
  показов → действий за 28 дней по каждому варианту (§6).
- Редактор варианта: поля по `fields`, счётчик длины, подсветка подстановок, **живой
  предпросмотр** в виде настоящей карточки (пустая комната, строка главной, новость).
- Проверки при сохранении (сервер, не только клиент):
  - длина в пределах `maxLength`; подстановки только из `placeholders`;
  - только текст: никаких HTML, ссылок и URL; `**жирный**` — если `bold`;
  - словарь запретов голоса (ADR-265 §2.2) и эмодзи — отказ с объяснением;
  - глоссарий (ADR-265 §2.4) — предупреждение, не отказ;
  - в слоте остаётся хотя бы один включённый вариант на каждый язык.
- Публикация: роль оператора, код TOTP не старше 15 минут (как прочие изменяющие действия
  консоли, ADR-262), обязательная причина, запись `hint.published` в аудит с версией.
- «Откатить» — публикует предыдущую версию одной кнопкой (тоже с причиной и аудитом).
- Рендер у людей — только текстовыми узлами; подстановки — экранированные значения.

## 5. Выбор варианта у человека

Не меняется (ADR-268 §2): номер визита по кругу среди **включённых** вариантов, условие слота
`when`, «пока не освоил», одна подсказка на экран. Оператор влияет только на набор вариантов.

## 6. Как понять, что слова работают

- Метрики `hint.shown { slot, variant }` и `hint.acted { slot, variant }` — агрегатами за день
  по установке, без людей и организаций (не больше одного счёта на браузер за визит).
- В «Словах» рядом с вариантом — «показали N, сделали M (доля)» за 28 дней; вариант с долей
  заметно ниже других — кандидат на правку. Решение — человека, автоматического отключения нет.

## 7. Этапы

1. Реестр слотов с `defaults`, перевод существующих подсказок на него (тексты из `i18n`),
   `hints:check`.
2. Таблица, `GET /hints`, клиентский кеш с фолбэком.
3. Раздел «Слова» в консоли: редактор, проверки, предпросмотр, публикация, откат, аудит.
4. Метрики `hint.*` и доли в консоли; `hints:export/import`.

## 8. Приёмка

- [ ] Без строк в `hint_texts` продукт показывает те же подсказки, что до изменения (e2e).
- [ ] Оператор публикует новую формулировку пустой комнаты — после перезагрузки у человека
      новый текст; без перезагрузки — старый; откат возвращает прежний.
- [ ] Сервер отклоняет текст с HTML, URL, чужой подстановкой, эмодзи, запрещённым словом и
      сверх длины — с понятной причиной (db-тест на каждый случай).
- [ ] В подсказке с подстановкой `{name}` значение `<b>x</b>` показывается как текст (e2e).
- [ ] Публикация без свежего TOTP — окно кода; аудит содержит версию и причину.
- [ ] Слотов в зонах денег, удаления, безопасности и права нет (тест реестра по списку экранов).
- [ ] РФ и ЕС независимы: публикация в одной установке не меняет другую; экспорт/импорт
      переносит черновики.
