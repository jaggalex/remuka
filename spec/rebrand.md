# Ребрендинг: remo → Ремука (Remuka), домены и ссылки

ТЗ к **ADR-254**. Статус: предложено, 2026-11-22. Документ написан для исполнителя (человека
или агента). Прежде чем менять код, прочитайте `AGENTS.md`, ADR-254, `spec/mail.md`
(ADR-246), `spec/support.md` (ADR-250), `spec/ai-gateway.md` (ADR-251) и
`spec/payment-providers.md` (ADR-248).

## 0. Зачем и что в объёме

Продукт переименовывается: **remo → Ремука / Remuka**. Куплены домены `remuka.com` и
`remuka.ru`. Публичные адреса переезжают с `remo.letii.ru` и `docs.remo.letii.ru`.
Переименовать нужно до запуска биллинга и почты, пока имя не попало в чеки, оферту,
кабинеты платёжных сервисов и DNS почтового домена.

**В объёме:**

1. Один источник имени и адресов бренда — модуль `brand` для браузера и сервиса (§3).
2. Всё, что видит человек: интерфейс RU/EN, письма, экспорт, файлы бэкапа, справка, гайд,
   README, страница «О программе», MCP, подписи для провайдеров ИИ (§4).
3. Новая карта доменов и переезд со старых адресов без поломанных ссылок, сессий
   API-клиентов и вебхуков (§5–6).
4. Политика товарного знака для форков AGPL (§7).
5. Проверка `pnpm brand:check`, которая не даёт старому имени и старым доменам вернуться (§8).

**Вне объёма:** новый визуальный стиль интерфейса и новый лендинг (отдельные задачи, см.
концепцию бренда), выкладка установки РФ на `app.remuka.ru` (§5.1 — только устройство и адреса),
переименование внутренних идентификаторов (§2).

## 1. Правила, которые нельзя нарушить

1. **Публичное имя меняем, кодовое имя оставляем.** Всё, что видит человек, говорит
   «Ремука» или «Remuka». Всё, на что опираются чужие установки, скрипты и данные,
   остаётся `remo` (§2). Ни одна существующая установка self-host не должна ломаться
   после обновления.
2. **Ни одной битой ссылки.** Каждый старый публичный URL отвечает переадресацией на новый
   с тем же путём и query, или проксируется (§6). Срок — не меньше 12 месяцев.
3. **Один источник имени.** Строки «Ремука», «Remuka» и новые домены пишутся в коде только
   в модуле `brand` (§3) и в i18n. Компоненты, шаблоны писем и скрипты берут их оттуда.
4. **Русский текст не меняем `sed`-ом.** «remo» в русских предложениях не склоняется, а
   «Ремука» склоняется (§4.3). Каждое русское предложение правится руками или агентом по
   одному, с проверкой падежа.
5. **Старое имя остаётся только как история.** Допустимо «Ремука (раньше remo)» в README,
   changelog и на странице «О программе» — полгода после переезда. Больше нигде.
6. **Секреты не трогаем.** `.config/remo/deploy.env`, `backups/` и `production.env` — не в
   git и не в ТЗ. Значения доменов в них меняет оператор (§9, этап 0).

## 2. Что остаётся `remo` (кодовое имя)

Это внутренние контракты. Их видят разработчики и операторы, а не пользователи;
переименование сломало бы чужие установки, данные и интеграции.

| Что | Пример | Почему остаётся |
|---|---|---|
| Пакеты монорепозитория | `@remo/sync`, `@remo/doc`, корневой `remo` | Внутренние, не публикуются; импорты по всему коду |
| Переменные окружения | около 130 переменных `REMO_*` | Файлы окружения всех self-host установок |
| Роли и схема БД | `remo_app`, `remo_owner` | RLS (ADR-178), миграции |
| HTTP-заголовки | `X-Remo-Signature`, `X-Remo-Event`, `X-Remo-Upstream` | Проверка подписи вебхуков у получателей; контракт шлюза ИИ |
| Метрики | `remo_ws_connections_total` и др. | Дашборды и алерты |
| Ключи хранилища браузера | `remo.identity`, `remo.session`, `remo.settings` | Иначе всех разлогинит и сбросит настройки |
| Формат бэкапа | `manifest.format = "remo.board.backup"`, `format = "remo.board"` | Старые бэкапы должны читаться всегда |
| Каналы `postMessage` | `remo:support:*` | Контракт с виджетом поддержки |
| Деплой | `/srv/remo`, `remo-sync.service`, `remo-web`, `remo-ai-gateway`, `remo-gw` | Инфраструктура операторов |
| Константы сборки | `__REMO_VERSION__` и др. | Внутренние |

Правило записывается в ADR-254 и в `AGENTS.md` одной строкой (§9, этап 1).

## 3. Модуль `brand` — один источник

Новый пакет `packages/brand` по образцу `@remo/text`: plain ESM, `.d.ts` рядом, без сборки,
чтобы его загружали и браузер, и `apps/sync`.

```js
// packages/brand/index.mjs
export const BRAND = {
  name: { ru: "Ремука", en: "Remuka" },     // в тексте, с заглавной
  wordmark: { ru: "ремука", en: "remuka" }, // только в логотипе
  pronunciation: { ru: "ремУка", en: "re-MOO-ka" },
  formerly: "remo",                          // для строки «раньше remo»
  site: { ru: "https://remuka.ru", en: "https://remuka.com" },
  app: "https://app.remuka.com",
  docs: "https://docs.remuka.com",
  status: "https://status.remuka.com",
  source: "https://github.com/jaggalex/remuka",
  contact: { hello: "hello@remuka.com", support: "support@remuka.com", security: "security@remuka.com" },
};
export function brandName(locale) { /* ru → "Ремука", иначе "Remuka" */ }
```

- **Адреса `app`, `docs`, `status` в `BRAND` — это адреса облака Ремуки.** Установка
  self-host берёт свои адреса из env, как сейчас: `REMO_APP_ORIGIN`, `REMO_DOCS_ORIGIN`,
  `REMO_SUPPORT_ORIGIN`. `BRAND` — значение по умолчанию и источник для документации.
- **Имя экземпляра.** Новая необязательная переменная `REMO_PRODUCT_NAME`. Если задана, это
  имя показывается в интерфейсе, письмах и экспорте вместо «Ремука/Remuka». Существующая
  `REMO_MAIL_PRODUCT_NAME` остаётся как устаревший синоним: читается, если новой нет, и
  пишет предупреждение в лог один раз при старте. Так оператор форка выполняет §7 одной
  строкой.
- Браузер получает действующее имя экземпляра от сервиса при старте — тем же маршрутом, что
  отдаёт возможности почты и биллинга; если такого маршрута нет, добавить `GET /api/config`.
  Не из сборки: один образ подходит всем установкам.
- `apps/web/src/about.ts` берёт `name`, `homepage`, `source` из `brand`. `author`, `license`,
  `year` остаются как есть.

## 4. Что меняется для человека

### 4.1 Интерфейс и сборка

| Место | Сейчас | Станет |
|---|---|---|
| `apps/web/index.html` `<title>` | `remo` | «Ремука» или «Remuka» по языку интерфейса; до загрузки — «Remuka» |
| favicon `remo-logo.svg` | знак remo | тот же знак (ADR-254), файл `remuka-mark.svg`; старый путь отдаётся ещё 12 месяцев |
| `about.ts` → меню аккаунта | `remo 0.8.0 · build N` | `Ремука 0.8.0 · build N`, с `REMO_PRODUCT_NAME` — имя экземпляра |
| Логотип в верхней панели (`BoardTopbar`) | `remo` | словесный знак «ремука» или «remuka» строчными |
| i18n RU и EN | 15 строк со словом remo в 7 файлах: `ru-work`/`en-work`, `ru-support`/`en-support`, `ru-collab`/`en-collab`, `en-core` | через `{product}` из `brandName`, с правильным падежом (§4.3) |
| Экспорт PNG Free | водяной знак (проверить, есть ли в нём имя) | «Ремука · remuka.com» или «Remuka · remuka.com» |
| PDF-метаданные (Creator, Producer) | remo | Remuka |
| Имя файла бэкапа (`sync-export.mjs`) | `<slug>.remo-backup.json` | `<slug>.remuka-backup.json`; импорт принимает оба имени, формат определяется по `manifest.format` |
| MCP `serverInfo.name` | `remo` | `remuka`; `title` — «Remuka» |
| Подпись запросов к OpenRouter (`ai.mjs`, `X-Title`) | `remo` | `Remuka`; `HTTP-Referer` — `BRAND.site.en` |
| User-Agent вебхуков (`webhooks.mjs`) | `remo-webhook/1` | `remuka-webhook/1 (+https://remuka.com)` |
| Тема справки `content/help/about.remo` | slug `about.remo` | `about.remuka`; старый slug переадресуется на новый |

Тексты в i18n остаются в i18n (ADR о локализации). Имя продукта подставляется параметром
`{product}`, а не вписывается в строку: так `REMO_PRODUCT_NAME` работает везде.

### 4.2 Письма

- Имя отправителя: «Ремука» для писем на русском, «Remuka» для писем на английском, по
  языку получателя. С `REMO_PRODUCT_NAME` — это имя.
- Адрес отправителя облака: `no-reply@mail.remuka.com`. Домен отправки в Resend —
  `mail.remuka.com` (поддомен, чтобы репутация рассылки не задевала основной домен).
- Темы и тексты всех шаблонов (`mail-templates.mjs`) — через `brandName(locale)`.
  Тест `defaults the product name to remo` меняется на `Remuka`.
- В подвале писем: ссылка на `BRAND.site` по языку и `support@remuka.com`.
- `spec/mail.md` §§ с примерами `remo <no-reply@…>` обновляются в том же PR.

### 4.3 Как писать имя

| Падеж | Русский | Пример |
|---|---|---|
| Именительный | Ремука | Ремука сохраняет правки сама |
| Родительный | Ремуки | ключ для Ремуки, бэкап Ремуки |
| Дательный | Ремуке | доступ к Ремуке |
| Винительный | Ремуку | перенесите обсуждение в Ремуку |
| Творительный | Ремукой | работать с Ремукой |
| Предложный | Ремуке | в Ремуке, о Ремуке |

- В тексте имя пишется с заглавной: «Ремука», «Remuka». Строчными — только в логотипе.
- В английском без артикля: «in Remuka», «Remuka keeps your edits».
- Глагола от имени нет: никаких «ремукнуть».
- Где падеж неудобен, перестраивайте фразу: «Это не бэкап комнаты remo» → «Это не бэкап
  комнаты Ремуки» или «Этот файл — не бэкап комнаты».
- Если строка с `{product}` требует падежа, а `REMO_PRODUCT_NAME` задан, используется
  именительный в конструкции «в сервисе {product}». У i18n два варианта строки: для
  бренда (со склонением) и для своего имени (без склонения).

## 5. Карта доменов

Облако сейчас одно, в ЕС. Регион РФ пока только резервируется.

| Адрес | Назначение | Примечание |
|---|---|---|
| `remuka.ru` | Лендинг на русском | Канонический для RU; `hreflang` на `remuka.com` |
| `remuka.com` | Лендинг на английском, `remuka.com/ru` → 301 на `remuka.ru` | Канонический для EN |
| `www.*` | 301 на апекс того же домена | |
| `app.remuka.com` | Приложение (web + sync + API + MCP + WebSocket), регион ЕС | Новый `REMO_APP_ORIGIN` |
| `app.remuka.ru` | Приложение **установки РФ** — отдельная установка со своей базой на сервере в России | Без проксирования и переадресации в ЕС; аккаунты двух установок не связаны (§5.1) |
| `docs.remuka.com` | Гайд RU и EN, `llms.txt`, `llms-full.txt` | Пути `/guide/ru/…`, `/guide/en/…` сохраняются |
| `docs.remuka.ru` | Тот же гайд, отдаёт установка РФ | Канонический адрес страниц — `docs.remuka.com` (`<link rel="canonical">`), чтобы поиск не видел дублей |
| `api.remuka.com`, `api.remuka.ru` | Зарезервированы на будущее (адрес для интеграций) | Сейчас не используются: DNS-записи удалить. Адрес без сертификата выглядит как поломка |
| `status.remuka.com` | Статус сервиса | Пока может вести на внешний статус-сервис |
| `support.remuka.com` | Chatwoot (ADR-250) | `REMO_SUPPORT_ORIGIN` |
| `agents.remuka.com` | Шлюз ИИ, только внутренняя сеть (ADR-251) | Из интернета не открывается |
| `mail.remuka.com` | Домен отправки Resend | SPF, DKIM, DMARC `p=quarantine` |

Почтовые ящики людей: `hello@`, `support@`, `security@`, `billing@` на `remuka.com`.
`security@` указывается в `SECURITY.md` и `/.well-known/security.txt` приложения.

Лендинг отделён от приложения: у лендинга свой кэш и CSP, а приложение не тащит
маркетинговые скрипты. Сами лендинги в этом ТЗ не делаются — только домены и
переадресации.

### 5.1 Две установки: ЕС и РФ

Решение владельца от 2026-11-22: облако — это **две независимые установки**, без
проксирования между ними. Так устроено уже сейчас (`docs/self-hosting.md`, «Two independent
installations»): у каждой свой сервер, база, секреты, бэкапы и история релизов.

| | Установка ЕС | Установка РФ |
|---|---|---|
| Сервер | 192.0.2.10 | 192.0.2.20 (временный, переедет) |
| Сайт | `remuka.com` | `remuka.ru` |
| Приложение | `app.remuka.com` | `app.remuka.ru` |
| Гайд | `docs.remuka.com` | `docs.remuka.ru` |
| Язык по умолчанию | EN | RU |
| Валюта и платёжные сервисы (ADR-247, 248) | USD; сервисы для иностранных карт | RUB; ЮKassa и другие российские |
| Отправка почты | Resend, `mail.remuka.com` | `mail.remuka.ru`; провайдер — решение юриста (Resend в США — трансграничная передача; драйвер `smtp` позволяет российского провайдера) |
| Зона cookie (ADR-255) | `eu` | `ru` |
| Конфигурация выкладки | `.config/remo/com.env.local` | `.config/remo/ru.env.local` |

Следствия:

- **Аккаунты и комнаты не общие.** Человек регистрируется в одной установке. Перенос — экспорт
  бэкапа комнаты и импорт в другой установке. На сайтах это говорится одной строкой рядом с
  кнопкой регистрации, а кнопка ведёт в приложение своей зоны.
- **Каждая установка — свой `REMO_APP_ORIGIN`, свои ссылки в письмах.** `BRAND.domains`
  описывает обе: `app`, `docs`, `site` для ЕС и `appRu`, `docsRu`, `siteRu` для РФ. Ссылка
  «на сайт» в интерфейсе ведёт на сайт своей установки (по `REMO_APP_ORIGIN`), а не по языку.
- **Старые аккаунты остаются в установке ЕС.** Все, кто зарегистрировался на `remo.letii.ru`,
  живут на сервере ЕС. Предлагать ли российским пользователям перенос в установку РФ, и в
  какой срок, — вопрос к юристу (локализация данных).
- **Сервер РФ временный.** Переезд сервера — обычная процедура «бэкап → новый сервер →
  восстановление → смена DNS»; адреса не меняются.

## 6. Переезд со старых адресов

Старые хосты продолжают работать минимум 12 месяцев. Способ зависит от типа запроса.

| Старый адрес | Что делаем | Почему |
|---|---|---|
| `remo.letii.ru` — страницы приложения (GET, HTML) | **301** на `app.remuka.com` с тем же путём и query | Закладки, ссылки на комнаты, публичные ссылки просмотра |
| `remo.letii.ru/api/*`, `/mcp`, вебхуки входящих платежей | **Прокси** на новый upstream 6 месяцев, с заголовками `Deprecation: true` и `Link: <https://app.remuka.com…>; rel="successor-version"`. Затем **308** | POST не всегда идёт за 301; токены интеграций и MCP-клиенты настроены на старый адрес |
| `remo.letii.ru` — WebSocket | Прокси 6 месяцев; затем сервер закрывает соединение с кодом `4001 moved` и адресом в причине. Клиент при этом коде перезагружает страницу | Открытые вкладки и PWA не умеют идти за 301 по WS |
| `remo.letii.ru/help/*` | 301 на `app.remuka.com/help/*` | |
| `docs.remo.letii.ru/*` | 301 на `docs.remuka.com/*` с тем же путём | Внешние ссылки и поисковики |
| `remo.letii.ru/remo-logo.svg` | Отдаётся как есть 12 месяцев | Встроенные картинки |

**Сессии.** Cookie привязаны к хосту, поэтому после переадресации на `app.remuka.com`
пользователь войдёт заново. Это допустимо один раз. Перед переездом показываем в
приложении баннер «Ремука переезжает на app.remuka.com — войдите заново после [дата]» за
7 дней (тексты в i18n).

**Источники разрешённых origin.** На время переезда сервис принимает оба origin. Новая
переменная `REMO_APP_ORIGIN_ALIASES` (список через запятую) используется в проверке Origin
у WebSocket, в CORS и в проверке ссылок-приглашений. Канонический адрес в письмах и
ссылках — только `REMO_APP_ORIGIN`.

**Ссылки, которые уже разосланы.** Приглашения и ссылки сброса пароля со старым хостом
продолжают работать через 301: токен в пути и query сохраняется.

**PWA.** Установленное приложение со старого origin не мигрирует само. Баннер на старом
origin предлагает открыть `app.remuka.com` и установить заново.

**Платёжные сервисы (ADR-248).** Адреса уведомлений в кабинетах ЮKassa, Robokassa и
остальных переводятся на `app.remuka.com`. Сайт магазина в профиле — `remuka.ru`. Смена
сайта у ЮKassa может потребовать повторной проверки магазина — сделать до запуска оплаты.
Прокси со старого хоста страхует уведомления, которые уже в пути.

**Конфигурация.** `deploy/nginx-remo.conf` получает примеры трёх серверных блоков: новый
хост приложения, старый хост с картой «301 / прокси» из таблицы выше, docs. Имя файла
остаётся (§2). Пример в `deploy/deploy.env.example`: новые `REMO_APP_ORIGIN`,
`REMO_DOCS_ORIGIN`, `REMO_APP_ORIGIN_ALIASES`.

## 7. Товарный знак и форки

Код — AGPL-3.0, имя и знак — нет. Это уже сказано в README про remo; переносим на Ремуку и
даём оператору форка простой способ соблюсти правило.

- Новый файл `TRADEMARKS.md`: имя «Ремука», «Remuka» и знак принадлежат автору. Форки и
  сторонние облака не используют их как имя своего сервиса. Свой сервер «для себя» и
  неизменённая сборка — можно. Ссылка «основано на Ремуке» — можно.
- В `docs/self-hosting.md`: чтобы показать своё имя, задайте `REMO_PRODUCT_NAME`.
- Заявка на товарный знак в ФИПС (классы 9 и 42) подаётся владельцем отдельно; в ТЗ это
  только строка чеклиста этапа 0.

## 8. Проверка `pnpm brand:check`

Скрипт `scripts/brand-check.mjs`, подключается в `pnpm verify`.

Падает, если находит:

1. Слово `remo` как отдельное слово (без учёта регистра, не `@remo/`, не `REMO_`, не
   `remo_`, не `remo.`, не `remo:`, не `X-Remo-`) в файлах, которые видит человек:
   `apps/web/src/i18n/**`, `apps/web/index.html`, `apps/sync/mail-templates.mjs`,
   `content/help/**`, `guide/**`, `README.md`, `docs/self-hosting.md`.
2. `letii.ru` в любом отслеживаемом файле, кроме `deploy/nginx-remo.conf` (блок старого
   хоста), `CHANGELOG*`, `ADR.md`, `spec/rebrand.md`.
3. Строки «Ремука», «Remuka», `remuka.com`, `remuka.ru` вне `packages/brand`, i18n,
   документации, README, `TRADEMARKS.md` и `deploy/*.example`.

Разрешённые исключения перечислены в одном списке в начале скрипта, с комментарием
«почему» у каждого. Строка «раньше remo» в README и на странице «О программе» —
исключение до даты, записанной в списке; после неё проверка снова падает и напоминает
убрать строку.

Сгенерированные каталоги (`docs-site/`, `ui-inventory/`, `e2e-report/`, `backups/`,
`node_modules/`) не проверяются.

## 11. Решения, принятые по умолчанию

Принято исполнителем ТЗ; владелец может поменять до этапа 1.

1. **Ударение — ремУка.** Подсказка произношения есть в `BRAND` и на лендинге.
2. **Агент в интерфейсе остаётся «агентом».** Имя «Подмастерье» из концепции бренда — не в этом ТЗ.
3. **Знак не меняется** — три фигуры remo, словесный знак меняется на «ремука» / «remuka».
4. **Лендинг отдельно от приложения:** `remuka.ru` и `remuka.com` — сайт, `app.remuka.com` — продукт.
5. **Репозиторий остаётся у `jaggalex`**, переименовывается в `remuka`. Если позже появится организация `remuka` на GitHub, перенос — отдельным шагом, GitHub сохранит переадресацию.
6. **Приложение — на `app.remuka.com`**, сайт — на апексе (подтверждено владельцем 2026-11-22). Пока лендинга нет, апекс отдаёт **302** на приложение своей зоны, не 301 и не 308.
7. **`api.*` — на будущее**, сейчас не используются (подтверждено 2026-11-22).
8. **Две независимые установки, ЕС и РФ, без проксирования** (подтверждено 2026-11-22), §5.1.
