# Приёмка клиентского пути через интерфейс

Задание для тестировщика (человека или агента с браузером). Статус: 2026-11-23. Цель — пройти
сценарии, которые обещают ТЗ и юридические документы, и получить **чек-лист готовности**:
что работает, что работает частично, что сломано, что ещё не сделано.

Сценарии построены по ТЗ (`spec/*.md`, `content/legal/*`), а не по коду: так видно и
неработающее, и нереализованное. Результаты вносятся в таблицу «Ремука — чек-лист готовности
UI» (ссылка в сообщении владельца); там же сводка по разделам.

## 1. Стенд

Проходить на **тестовом стенде**, не на проде: сценарии создают аккаунты, платежи и удаляют
данные.

- Две установки, как в облаке: зона `ru` и зона `eu` (`spec/cloud-zones.md`). Если стенд один —
  проходить его дважды, меняя `REMO_COMPLIANCE_ZONE` и `REMO_APP_ORIGIN`.
- Версия — та, что принимается (`/api/health` → `version`, `commit` записать в таблицу).
- `REMO_LEGAL_ALLOW_DRAFTS=1` — черновики документов из `content/legal/`.
- Почта — реальный драйвер на тестовые ящики (лучше Gmail и Яндекс), не `console`: часть
  сценариев проверяет письма.
- Платежи — тестовые подключения (`pnpm billing:providers create --mode test …`) с тестовыми
  картами провайдера, включая карту отказа.
- Шлюз ИИ — тестовый ключ провайдера с маленьким лимитом.
- Чат поддержки — включён (`REMO_SUPPORT_PROVIDER=chatwoot`) или сценарий S-71 отмечается
  «Не проверено» с причиной.
- Для S-85 нужна возможность сдвинуть срок: `pnpm account:delete --user … --now` или правка
  `deletion_requested_at` на стенде.
- Для S-03 нужны старые хосты, направленные на стенд; если их нет — «Не проверено».

## 2. Участники и аккаунты

| Кто | Зачем |
| --- | --- |
| Посетитель | чистый профиль браузера, без входа |
| Владелец | создаёт организацию, платит, приглашает |
| Коллега | приглашается по e-mail, работает вдвоём с владельцем |
| Гость | открывает комнату по ссылке |
| Пользователь до выкладки | аккаунт, созданный на предыдущей версии (для S-16) |
| Оператор | роль выдана `pnpm operator:grant`, телефон с приложением-аутентификатором |

Нужны два браузера (или обычное окно и окно в другом профиле) и телефон.

## 3. Как отмечать результат

| Статус | Когда ставить |
| --- | --- |
| **Готово** | всё из «Ожидается» выполнено |
| **Частично** | основное работает, но часть ожидаемого нет — в «Комментарии» что именно |
| **Не работает** | функция есть, но сценарий не проходит (ошибка, потеря данных, неверный результат) |
| **Не реализовано** | функции нет в интерфейсе |
| **Не проверено** | нельзя проверить на этом стенде — в «Комментарии» почему |

- Для «Частично» и «Не работает» — скриншот или запись экрана и шаги в колонке «Дефект»
  (ссылка на задачу или текст).
- Любое появление старого имени «remo» в интерфейсе, письмах или файлах — отдельный дефект.
- Тексты, которые расходятся с юридическими документами (сроки, адреса, суммы), — тоже дефект:
  документы и продукт должны говорить одно и то же.
- Сценарий считается принятым только после повторной проверки исправления.

готово, частично, сломано, не реализовано и не проверено. Список «Не работает» и «Не
реализовано» — это план работ до запуска; «Не проверено» — что нужно добавить в стенд.
