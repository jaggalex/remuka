## Что это

**Журнал** — это история действий операторов: выдача и снятие роли, возвраты и кредиты, ручные оплаты, меры по жалобам, удаление аккаунта, события второго фактора. Он отвечает на вопрос «кто, когда, что и почему сделал», когда спор идёт о деньгах, доступе или жалобе.

Журнал только читают. В консоли его нельзя очистить, изменить или удалить строку.

## Фильтры

| Поле | Что принимает |
|---|---|
| Действие | начало имени действия, например `billing.` или `abuse.` |
| Оператор | id аккаунта оператора |
| Организация | id организации |
| С | начало периода |
| По | конец периода |

На сервере тот же набор доступен запросом; в консоли под полями стоит кнопка **Показать**. Без фильтров консоль просит последние 200 строк, запрос по умолчанию — 100; максимум — 500.

Границы дат в консоли считаются от начала дня по UTC. Если нужен весь последний день, укажите в поле **По** следующий день: иначе строки после полуночи UTC в выборку не попадут.

## Что в строке

| Колонка | Значение |
|---|---|
| Когда | дата и время в часовом поясе браузера |
| Кто | адрес оператора; «сервер», если действие выполнила команда без человека |
| Что | имя действия, например `billing.refunded` |
| Где | организация, если действие к ней относится |
| Причина | текст, который оператор указал в `--reason`; если причины нет — объект действия |

## Какие действия попадают

| Группа | Действия |
|---|---|
| Роль | `operator.granted`, `operator.revoked` |
| Второй фактор | `mfa.enabled`, `mfa.step_up`, `mfa.recovery_used`, `mfa.recovery_regenerated`, `mfa.reset`, `mfa.locked`, `mfa.disabled` |
| Деньги | `billing.refunded`, `billing.credit_granted`, `billing.invoice_marked_paid`, `billing.plan_granted`, `billing.plan_ended` |
| Жалобы | `abuse.link_disabled`, `abuse.board_hidden`, `abuse.org_suspended`, `abuse.reverted` |
| Аккаунт | `account.delete_operator`, `account.purged` |

Список не закрыт: сюда попадают и другие действия продукта, у которых есть организация или объект. Фильтр по началу имени помогает сузить выборку.

## Что считается доказательством действия

Доказательство — строка журнала, в которой есть время, автор, действие, объект и причина. Команды устроены так, чтобы такая строка появлялась у каждого изменения прав, денег, меры или аккаунта, а без автора команда отказывала. У возврата, кредита и меры причина обязательна; у назначения тарифа она записывается командой.

- Если строки нет, действие через команду не проходило. Это не значит, что его не было: аварийное вмешательство в базу идёт мимо журнала, поэтому его причину фиксируют в обращении.
- Строка называет объект: id платежа, id меры, id аккаунта. По нему видно, что именно изменено.
- Публичная причина меры и внутренняя причина — разные поля. В журнал попадает внутренняя; клиент видит публичную в письме и на плашке.
- Администратор организации видит журнал своей организации в приложении. Общий журнал установки видит только оператор.

## Проверка

- Выдайте тестовую роль и найдите строку `operator.granted` с вашей причиной и вашим адресом.
- Отфильтруйте по действию `billing.` — останутся только денежные строки.
- Отфильтруйте по id организации — останутся строки этой организации.
- Строка без человека показывает «сервер», а не пустую ячейку.
- Повторная команда, которая ничего не изменила, не добавляет вторую строку об изменении.

## Если что-то пошло не так

| Симптом | Причина | Что делать |
|---|---|---|
| «Записей нет» | фильтр слишком узкий или период пуст | очистите фильтры и расширьте даты |
| Не видно вчерашних строк | граница **По** — начало дня UTC | укажите следующий день |
| Ошибка фильтра по оператору или организации | id должен быть полным uuid | скопируйте id из карточки клиента |
| Строк больше, чем помещается | в консоли предел 500 | сузьте период или действие |
| Действие есть, причины нет | команда выполнена не через оператора или старая запись | проверьте объект и время; для новых действий причина обязательна |
