## Что получится

Подтверждённый аккаунт получает роль оператора установки, а вы — доступ к `/operator` после подключения второго фактора. Роль выдаётся только с сервера: маршрута в приложении для этого нет.

## Подготовка

- Доступ к серверу и каталогу выпуска, откуда запускается сервис.
- Аккаунт, зарегистрированный обычным образом, с подтверждённым адресом. Неподтверждённый аккаунт роль не получит.
- Загруженное окружение выпуска: команда читает `.env` из каталога, где вы её запускаете, и берёт оттуда строку подключения к базе.
- Решение, кто ещё будет оператором. Держите двух: сброс второго фактора выполняет другой оператор.

## Шаги

1. Зарегистрируйтесь в приложении и подтвердите адрес из письма.
2. На сервере, в каталоге выпуска:

   ```sh
   cd /srv/remo
   pnpm operator:grant --email ops@example.com --as ops@example.com --reason "bootstrap"
   pnpm operator:list
   ```

   Первый оператор называет сам себя: других операторов ещё нет. Это единственное исключение из правила «автор должен уже иметь роль».
3. Откройте `https://<адрес установки>/operator` и подключите второй фактор. Без него консоль не откроется.

## Автор команды

Каждая изменяющая команда называет автора: `--as <id|email>` или переменная `REMO_OPERATOR`. Без автора команда отказывает и печатает подсказку. Это относится и к выдаче роли, и к деньгам, и к мерам по жалобам: в журнале не бывает строк с пустым автором.

При выдаче первой роли действует одно исключение: если операторов в установке ноль, а `--as` совпадает с адресом, которому выдают роль, команда разрешает самовыдачу. Любая следующая команда требует существующего оператора.

## Выдать и снять роль

```sh
pnpm operator:grant  --email person@example.com --reason "ведёт поддержку" --as ops@example.com
pnpm operator:revoke --email person@example.com --reason "ушёл из команды" --as ops@example.com
pnpm operator:list
```

- `grant` требует действующий аккаунт с подтверждённым адресом.
- `revoke` отказывает, если это последний оператор: иначе выдать следующую роль будет некому.
- Снятие роли не завершает сессии аккаунта. Следующий запрос консоли от этого аккаунта получит 404.
- Обе команды пишут строку в журнал: `operator.granted` или `operator.revoked`, с причиной и автором.

| Флаг | Что значит |
|---|---|
| `--email` | аккаунт, который получает или теряет роль |
| `--reason` | причина; попадает в журнал, обязательна |
| `--as` | автор команды: id или адрес оператора |
| `REMO_OPERATOR` | тот же автор, если `--as` не указан |

## Проверка

- `pnpm operator:list` печатает адрес, id и дату выдачи; у выданной роли виден автор.
- Под новым аккаунтом `/operator` открывается после подключения второго фактора.
- Под аккаунтом без роли `/operator` отвечает «Страница не найдена».
- В журнале есть строка `operator.granted` с вашей причиной.
- Команда без `--as` и без `REMO_OPERATOR` отказывает, не открывая базу.

## Если доступ потерян

| Что потеряно | Что делать |
|---|---|
| Пароль | восстановите его письмом на подтверждённый адрес; роль остаётся за аккаунтом |
| Приложение-аутентификатор | войдите резервным кодом; если кодов нет — [сбросьте второй фактор](/guide/operator/totp) с другого оператора |
| Почта и второй фактор одновременно | восстановите почту. Пока почта недоступна, сброс делает другой оператор; если его нет, помогает только вмешательство на сервере от владельца базы и повторный bootstrap |
| Аккаунт удалён | роль исчезает вместе с аккаунтом; если операторов не осталось, повторите bootstrap |

Держите двух операторов: единственный оператор без доступа к почте и к приложению останавливает управление установкой. Аварийное вмешательство в базу не пишет строку в журнал — зафиксируйте причину в обращении.

## Если что-то пошло не так

| Сообщение | Причина | Что делать |
|---|---|---|
| `has no confirmed address` | адрес не подтверждён | подтвердите его в приложении и повторите |
| `is not an instance operator` | `--as` называет аккаунт без роли | укажите действующего оператора или используйте bootstrap |
| `LAST_OPERATOR` | попытка снять последнюю роль | сначала выдайте роль второму человеку |
| `no account with the address` | аккаунта нет на этой установке | зарегистрируйте его здесь; роль не переносится между установками |
| `DATABASE_URL is required` | окружение не загружено | запустите команду из каталога выпуска с его `.env` |
| `--as ... is required` | не назван автор | добавьте `--as` или `REMO_OPERATOR` |
