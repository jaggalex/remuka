# Юридические документы

Источник текстов для страниц `/legal/*` и для формы регистрации (ADR-256,
`spec/legal-acceptance.md`). Файл на редакцию: `<zone>/<doc>/<version>.<lang>.md`.
Метаданные — в `index.json`.

## Путь документа

1. **Черновик** (`"status": "draft"`). Текст можно править на месте. Страницы показывают плашку
   «Черновик» и `noindex`; форма регистрации работает — так проверяется клиентский путь.
   Установка с `NODE_ENV=production` отказывается стартовать с черновиком, у которого
   `required: "signup"`, если не задано `REMO_LEGAL_ALLOW_DRAFTS=1` (для тестового стенда).
2. **Правки юриста.** Юрист правит выгрузку в Word (`legal-drafts.docx`). Правки переносятся в
   этот же файл редакции, пока она черновик.
3. **Публикация.** Заполнить все `[квадратные скобки]`; в `index.json` поставить
   `"status": "published"` и `"effective": "ГГГГ-ММ-ДД"`, затем выполнить `pnpm legal:build`.
   Сборка записывает SHA-256 текста в `"sha256": { "<версия>": "<хеш>" }`. С этого момента файл
   не меняется — `pnpm legal:check` упадёт на другой хеш и попросит новую редакцию.
4. **Новая редакция.** Новый файл `2.<lang>.md`, `"current": 2`, снова `"status": "draft"` до
   публикации. Хеш первой редакции остаётся в `"sha256": { "1": … }`: старый текст доступен по
   `/legal/<doc>/v1`, и его неизменность проверяется так же, как текущего.

`lang` называет ровно один язык: одна редакция — один текст и один SHA-256, который получает
человек и записывает журнал принятий. Двуязычный документ — это две редакции или новая модель,
а не второй элемент массива.

`required: "signup"` — документ в форме регистрации. `reaccept: true` — новая редакция
спрашивается у всех аккаунтов при входе (окно), а оператор ставит письмо командой
`pnpm legal:notify --doc <doc>`. `withdrawable: true` — отдельное согласие, которое человек
может отозвать на странице «Документы»; у оферты и Условий использования флага нет.

## Сборка и проверка

| Команда | Что делает |
|---|---|
| `pnpm legal:build` | пишет `legal-site/<zone>/` (`/legal/<doc>`, `/legal/<doc>/v<N>`) и дописывает хеши опубликованных редакций в индекс |
| `pnpm legal:check` | проверяет индекс, тексты, хеши и (если `legal-site/` существует) устаревшие страницы; входит в `pnpm verify` |

`legal:check` падает, если:

- опубликованный текст изменился после записи хеша — нужна новая редакция;
- в опубликованном тексте остались `[...]` — сборка называет файл и строку;
- у документа с `required: "signup"` нет текста нужной редакции или языка;
- в дереве есть документ, файл или редакция, которых нет в индексе (ничего мимо реестра);
- у черновика зафиксирован хеш текущей редакции.

`legal-site/` — генерируемый каталог, в git его нет. Установка отдаёт свой зонный каталог как
`/legal/`: `legal-site/<zone>/` → `/legal/`, поэтому документы другой зоны на этом сайте
недоступны.
